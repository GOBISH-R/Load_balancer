How failures are handled

Load-balancing algorithmRound-robin: backends take turns, so equal servers get equal shares
CapacityNginx worker_connections 4096, 64 reusable keep-alive connections per backend; each backend runs 3 gunicorn processes × 16 threads
Passive health checkmax_fails=2 fail_timeout=10s: two failures mark a backend down for 10 s, then Nginx tries it again
Automatic retryproxy_next_upstream error timeout http_502 http_503 http_504, up to 2 tries
Connect timeoutproxy_connect_timeout 2s: a stopped server costs at most 2 s, not the 60 s default
Backend identificationX-Backend-Server and X-Upstream-Addr headers, $upstream_addr in the access log
